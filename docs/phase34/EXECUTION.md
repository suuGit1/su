# 第三、四阶段执行协议与真实状态

## 第三阶段

新增 `scripts/plan_phase3.py` 生成总交互预算阶梯，默认每方法每种子300/1200/4800回合等价预算，5种子；此预算含训练和末端选模，测试另计。预算足够与否须由曲线判断。各预算点独立重训，总研究成本须累计，不伪装成免费续训。保留ordinary、pareto、fixed、OLS、central、同信息MPC、未来信息Oracle。

| 每方法每种子总预算 | ordinary/central训练 | Pareto训练 | fixed总训练 | OLS总训练 |
|---|---:|---:|---:|---:|
| 300 | 298 | 292 | 294 | 292 |
| 1200 | 1198 | 1192 | 1194 | 1192 |
| 4800 | 4798 | 4792 | 4794 | 4792 |

每回合24步；fixed的选择6回合、OLS8回合、Pareto8回合、ordinary/central2回合。所有子策略分摊总训练量。禁用额外周期验证；执行后同时核对结果报告计数和逐交互ledger，失败、未知状态或未耗完预算不能冒充同预算成功。MPC/Oracle结果可跨预算复用，但不得重复计为新实验。

```bash
python scripts/plan_phase3.py --budgets 300,1200,4800 --seeds 1,2,3,4,5 --workers 1
# 检查生成的 plan.json 后，下条命令按固定计划实际训练。
python scripts/plan_phase3.py --budgets 300,1200,4800 --seeds 1,2,3,4,5 --workers 1 --execute
```

当前计划使用v4.2原协调器，不能把服务候选版结果归给这些训练。将候选协调器接入训练还必须保留actor对通信/CPU剩余资源分配的实际影响；服务研究版目前使用规则优先级，不能直接替换后声称仍是完整学习型C3。

固定偏好前沿由现有报告入口评估。新增日内切换入口：

```bash
python scripts/evaluate_preference_switch.py --checkpoint <检查点路径> --csv data/real/gb/profiles/test.csv --days 29 --output runs/switch_development
```

默认第0、8、16步切换为经济、碳、备用重点；三种actor模式共用同一环境偏好序列。冻结检查点、数据、实现指纹和切换表，检查训练/校准数据重叠。只有三月开发日期被允许。普通MAPPO应作为对偏好不敏感的负对照；记录原始动作、物理执行、安全干预和时变偏好效用。不用最后一步偏好加权整个回合。

当前仅用已有2回合检查点完成1日、双MAPPO各3模式的接口检查，不能替代5种子充分训练。HV参考点沿用[-100,-200,0]，IGD参考集只能取验证经验前沿。切换实验与固定偏好前沿是不同证据，不相互替代。
