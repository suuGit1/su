# 路线 A 第一批：通信—计算—控制基础闭环

项目名称：**Digital-Twin-Driven Communication–Computation–Control Co-Design for Safe Pareto Multi-Agent Energy Management in Cyber-Physical Virtual Power Plants**。

标题描述最终研究目标。本阶段实现可运行的基础闭环，尚未实现学习残差 Hybrid DT、校准不确定性、偏好条件 Pareto 策略及陈旧观测下的鲁棒安全保证。

## 执行时序与信息边界

1. 回合开始有一次同步初始化，初始化只包含当前状态与已接入 EV；初始化成本不计入后续运行统计。
2. 第 t 步策略和价值网络读取已完成计算的缓存，以及基础 DT 根据候选指令推演的状态。所有智能体共享同一个边缘缓存，属于共址策略执行；尚未模拟多边缘节点间通信。
3. 能源动作按 DT 估计解码。通信动作选择采样上传和带宽，计算动作分配各资源 DT 更新任务的 CPU。
4. 传感器在步首采样；上传队列先传输，传输完成才能进入计算队列。任务完成才能将采样时刻的数据写入 DT 缓存。禁止直接写入任务完成时刻的物理真值。
5. 本地安全层读取本地实时测量，对候选能源动作进行已有 MILP 校正，物理系统执行该动作。本地保护不受上行遥测延迟影响；候选指令下行和安全求解耗时尚未接入事件调度。
6. DT 只知道自己发出的候选指令；本地实际动作、分车执行结果、控制校正没有零时延反馈。收到旧时刻测量后，按指令历史重放至当前决策时刻。
7. 下一步策略读取更新后的缓存。物理真值仅用于日志中的误差核算；不进入 actor、critic，也不作为附加奖励。

运行顺序中能源执行与队列推进各自计算一次完整时间步。不存在步内重决策；即使任务提前完成，也在下一调度边界使用它。队列可见元数据含剩余 bit/cycle 和资源预算，实际遥测内容不可见。包长度包含序列化数据长度，因此工作量元数据可透露消息大小，但不能直接读取 payload。

## 智能体和动作

- `cyber_mode=off`：原有能源环境，普通 MAPPO、IPPO、固定权重 MAPPO 及 MILP/MPC 保留。
- `cyber_mode=fixed`：6 个能源智能体，上传全部开启，带宽/CPU 均分。
- `cyber_mode=joint`：6 个能源、6 个资源通信子智能体、6 个资源计算子智能体，共 18 个。每个智能体仍输出一个标量，复用官方 MAPPO 代码，采用共享参数和角色标识。这是三个职能组，不是三个独立标量智能体。

通信与 CPU 原始动作经过 `max(0,tanh(a))` 得到权重 w；分配量为 `budget*w/max(1,sum(w))`。通信正权重同时触发一次采样上传。零权重暂停相应队列；已有包不会被暗中传完。CPU 零权重暂停 DT 任务。分配给闲置队列的容量不自动重新分配；这些语义使无效分配真实产生后果。

每个 actor 观察包含 18 维 DT/配置特征、6 维 AoI、12 维队列元数据及 18 维角色编码，共 54 维。MAPPO critic 拼接这些受限观察，不读取额外真值。通信/计算成本计入共享团队奖励；没有额外的真值误差奖励。

本阶段 C3 训练入口仅启用普通 MAPPO/IPPO；固定权重三目标方法在原能源环境继续可用。C3 多目标碳与备用口径将在后续统一后接入，不能把能源模型指标直接贴到新闭环。

## 模型、单位和边界

`CyberSpec` 支持配置：总带宽 bit/s、CPU cycle/s、包额外 bit、DT 任务 cycle、每资源队列容量、随机丢包概率、任务截止时间、单位传输/计算能耗和电价。参数文件和解析后的快照进入检查点。

事件驱动模拟器精确推进传输/计算完成时刻，支持跨步积压、队列溢出丢弃和传输完成后的随机丢包。使用独立种子；没有重传、传播时延、信道衰落或并行共享内存竞争。计算任务仅包含 DT 更新；策略推理与安全求解尚未占用模拟 CPU。

时间单位为模拟秒，且每步长度严格为 `dt_hours*3600`。默认 15 分钟步长、10 kbit/s 总带宽、10^7 cycle/s CPU、每包额外 10^6 bit、每任务 10^9 cycle；这是用于触发跨步延迟的**压力假设**，不是测量得到的工业设备参数，不能用于宣称毫秒级实时控制性能。实际程序运行耗时与模拟事件时延不能混用。

通信和 CPU 能耗按实际服务的 bit/cycle 计费；没有空闲功耗/DVFS。基础设施能耗单独核算，不放入 IEEE33 馈线，也未转换为碳排放。

`cyber_dt_mode=physics`：ESS 守恒、已知 EV 的候选充电分配、DR 状态推演；外部量持久性保持。物理状态按局部范围裁剪，但不假装知道现场安全校正。`hold` 保持旧测量，仍根据已知申报期限移除到期车辆。未知新接入车辆只有对应遥测完成计算后才能进入 DT。

当前没有残差网络和校准不确定性；AoI 是陈旧程度指标，不是概率误差界。基础 DT 的误差可能因未知安全校正、未来到站与风光变化增长。

## 运行

在本阶段分支按 README 安装原有 MAPPO 和 IEEE33 依赖，无新增第三方算法依赖。

```bash
python -m vpp_mappo train --config configs/c3_smoke.json --output runs/c3_mappo
python -m vpp_mappo evaluate --checkpoint runs/c3_mappo/latest.pt --output runs/c3_eval --episodes 1
python -m vpp_mappo.cyber_probe --config configs/c3_smoke.json --output runs/c3_probe
python -m unittest discover -s validation -p 'test_stage*.py'
```

`cyber_probe` 在同一场景使用固定反馈控制器，对比正常链路、禁止上传、禁止 CPU、保持旧观测；它是因果探针，不是公平预算下的算法排名。

轨迹记录采样、传输完成、DT 完成、丢包、队列溢出事件及时间戳，并记录 AoI、任务时延、实际 bit/cycle、能耗、队列积压、DT 状态误差与安全校正量。截止时间违约分为已完成任务超时数和仍积压的超时任务数；不能只统计成功完成的任务。

原 `compare`/`baselines` 对 C3 配置明确拒绝执行，因为尚未提供读取同等 DT 信息的 MPC。`cyber_mode=off` 下原有 MILP/MPC 和配对比较正常保留；不能把完整真值能源优化器标为 C3 公平对照。

## 本次实测与下一步

验证了上传完成前不可读、CPU 完成前不可读、预算守恒、积压/丢包、延迟重放、未知到站隔离及 actor/critic 信息隔离。普通 MAPPO 完成两回合训练和独立场景重载，结果只说明入口可运行。

合成因果探针中正常链路完成 36 次有效更新，关闭上传或 CPU 后为 0；对应调度结果不同。但关闭通信/计算在该短场景反而成本较低，两回合训练后的确定性策略也没有产生有效 DT 更新。因此本阶段**没有证明通信协同收益、训练收敛或方法优越性**。必须继续检查本地安全层补偿、控制器策略与服务任务目标的影响。

下一批建议：在相同遥测限制下实现可比较的控制器；明确协调器跟踪任务、截止时间及风险预算，区分安全纠正和正常控制；再接入物理残差 DT、误差区间校准以及控制/求解任务计时。不要靠任意提高 AoI 奖励强行制造协同优势。
