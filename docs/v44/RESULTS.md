# v4.4机制修复：结果与边界

## 已完成的证据

1. 架构修复：停用通道清理、无效动作掩码、独立偏好编码、八回合分层偏好采样。
2. 价值修复：相同架构增加critic学习强度，首次200次、随后每批30次，输出层初始化增益1.0；actor每批仍5次。
3. 每轮四案例：同一个更新器的经济、碳、备用固定端点与条件策略；同种子43、同八个训练日期、各192次训练交互；各四种开发偏好×一天×24步=96次评估。每轮1152次完整交互，两轮2304次。没有选模，没有打开确认集。
4. 每轮全部384个开发执行步：AC越限0、备用核验失败0、失败评估0。该结果只覆盖这些测试，不能写成普遍安全保证。
5. 官方普通MAPPO及集中PPO在真实数据上各完成24步训练与检查点重载。五个新学习器测试、五个v4.2回归测试、四个服务投影测试通过。v4.3普通/Pareto旧检查点重载通过；完整七方法CLI预检通过。

## 价值函数为什么值得优先修

独立离线诊断仅使用已存八个训练回合，六个完整回合拟合、两个完整回合留出，不更新actor。原critic留出解释方差接近零；200次拟合后约为0.904/0.633/0.747，1000次后约0.763/0.888/0.696。并非越多越好；已有过拟合/日期差异迹象。该诊断支持价值学习不足，不证明部署控制提升。

独立初始化增益对比固定其余初始参数和离线目标：200次更新时，增益0.01留出解释方差约0.843/0.488/0.626；增益1.0约0.890/0.620/0.787。初始化与更新次数联合改变的在线结果不能把收益全部归于其中一个因素。

## 终端SOC仍是明确问题

价值修复后的开发日：条件策略经济偏好下运行成本1242.40、终端罚项364.96、SOC0.1850；同学习器经济端点运行成本1241.63、终端罚项333.34、SOC0.2167。储能目标SOC为0.55。总经济差距主要来自终端状态；不能把全部差距称为购电策略差。

纯碳/纯备用偏好把经济终端罚项权重设成零，这是现有目标的数学结果。若论文需要相同末端能源库存，必须另立公共终端服务约束并同步MPC/MILP、安全层和所有学习基线；本修复没有改变该实验问题。接下来先检验经济单偏好是否能在更多策略更新后学会恢复，再判断是否需要修改问题协议。

## 运行失败也保留

部分初次实验出现SQLite写入只读错误，保留原账本和未知调用，改到独立临时目录完成后导出。不得把未明调用标成未发生。第一轮32回合检查也遭进程中断：条件策略提交28回合、经济端点24回合，各一条未知调用；不计为公平完成对比，已保存现场另起完整重跑。

归档：architecture_evidence.zip、value_evidence.zip含模型、配置、逐步轨迹、预算及评估；architecture_source.zip包含首轮源码；机器汇总为architecture_report.json、value_report.json。32回合结果单独追加，不覆盖上述记录。

## 完成的32回合检查

固定经济端点与条件策略各训练768步、开发评估96步，总计1728步；预算与日期顺序匹配，全部开发评估AC越限/备用核验失败为0。经济端点总成本从八回合的1574.97降至1380.88（下降12.32%），终端SOC从0.2167升至0.4142。条件策略经济偏好总成本为1600.82，终端SOC0.1918。条件策略三目标训练解释方差已约0.955/0.970/0.952，仍没有追上经济端点。

因此，“只要critic拟合好了，多目标策略自然变好”不成立。还须检查偏好间的经验共享和信号质量。该32回合检查只有经济端点对照，不能称为完整三端点前沿实验。

## 外生基准候选的实际控制结果

相同种子、相同八个训练回合及相同开发日期，仅对训练奖励启用外生基准。条件策略192步训练+96步开发评估全部完成，未出现AC越限、备用核验失败。与八回合价值修复版本配对比较：

|请求偏好|总经济成本变化|碳排变化|备用变化|
|---|---:|---:|---:|
|经济|−2.273%|+0.0175%|+30.055%|
|碳|−1.392%|−0.0191%|+32.187%|
|备用|−2.210%|+0.0143%|+30.867%|
|均衡|−2.091%|+0.0083%|+31.840%|

经济/碳下降较好，备用上升较好。碳的变化很小，且并非所有偏好都下降，不能宣称显著减碳。经济偏好总成本1570.83=运行成本1242.11+终端罚项328.72，SOC0.2213。终端恢复仍不充分，跨日库存问题没有解决。

同状态动作偏好跨度从0.00694降至0.00320，但控制结果改善；优化动作跨度本身不是目标。候选已呈现经济偏好下成本最低、碳偏好下碳排最低；备用偏好下备用仍略低于经济偏好（3064.17 vs 3079.65），方向性验收没有全部通过。

这项比较只隔离训练信号变化，尚未包含同样中心化训练的三端点对照，不能据此声称优于固定权重。官方普通MAPPO与集中PPO在该奖励开关下各完成24步训练及重载，接口通过。

## 配对采样开关

32回合分层调度中，每个纯偏好只有4次，且对应不同外生日期，存在偏好与日期的有限样本混杂。新增`paired_preference_days`：每八个偏好共享同一外生日期与随机种子；所有方法使用同一映射，元数据记录实际种子。普通模式保持原日期顺序。配对调度与无效动作/critic等六项测试通过。

`configs/v44_paired_candidate.json`组合外生中心化与配对日期，已完成4回合端到端验收，默认不开。配对会减少给定回合数覆盖的独立日期，必须报告日期数及总交互；不能把重复日期当作额外独立样本。

配对验收四回合训练日期索引均为18，96步训练与96步开发评估完整，无未知调用、AC越限或备用核验失败；每个评估回合仍有5步区间guard不可行，不能把最终AC合格称为全程区间安全认证。该验收只有一个训练日期，不与八回合结果作性能改善比较。详见paired_report.json与paired_evidence.zip。

本轮完成的机制训练与开发交互共4512步，另有两轮官方/集中接口验收96步，合计4608步；中断尝试另列，不从总开销中隐藏。所有这些都是开发证据，确认性测试集仍未使用。
